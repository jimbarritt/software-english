# Tutorial (Diátaxis documentation type): a local reference for Software English

## Canonical sources

- Framework overview: https://diataxis.fr/
- Tutorial page: https://diataxis.fr/tutorials/

## What a tutorial is

Diátaxis names four documentation types: tutorials, how-to guides, technical reference, and explanation. It places these four in a systematic relationship and organises documentation around the structure of the need each type serves.

A tutorial is learning-oriented. Diátaxis defines it as an experience that takes place under the guidance of a tutor. Its purpose is the user's acquisition of skills and knowledge, not the completion of a task. In the framework's own words: "Its purpose is not to help the user get something done, but to help them learn."

Diátaxis distinguishes what a learner does from what a learner learns: "while a student will learn by doing, what the student does is not necessarily what they learn." A tutorial gives the learner theoretical knowledge, understanding, familiarity, and concepts, not only a completed task.

## Structural conventions

Diátaxis gives concrete writing guidance for a tutorial:

- Deliver visible results early and often. Every step the learner follows should produce a comprehensible result, however small.
- Ruthlessly minimise explanation. A tutorial is not the place for explanation.
- Focus on this problem, this action, this result. Guide the learner from step to concrete step, not through abstract concepts.
- Keep up a narrative of expectations, for example: `You will notice that…`; `After a few moments…`. State what the learner should see, so they know the step worked.
- Achieve perfect reliability. A tutorial must work for every user, every time. Each step and its result must be repeatable.
- Ignore options and alternatives. Keep the learner's attention on the path to the conclusion. Remove distracting explanation and link to it elsewhere instead.

## How this differs from a how-to guide

A tutorial is learning-oriented: it serves the learner's study, and its purpose is to help them learn. A how-to guide is goal-oriented: it serves a user who already has a specific practical objective, and its purpose is to help them get that task done. A tutorial prioritises the pedagogical experience of the learner; a how-to guide prioritises the correct completion of a real task by a user who already has some competence.
