# How-to guide (Diátaxis documentation type): cached reference for Software English

## Canonical sources

- Framework overview: https://diataxis.fr/

## What a how-to guide is

Diátaxis names four documentation types: tutorials, how-to guides, technical reference, and explanation. It places these four in a systematic relationship and organises documentation around the structure of the need each type serves.

A how-to guide is goal-oriented. Diátaxis describes it as concerned with work: "navigating from one side to the other of a real-world problem-field." It serves the already-competent user, described as someone "whom you can assume to know what they want to do, and to be able to follow your instructions correctly."

A how-to guide answers to a human project. Diátaxis frames this as showing "what the human needs to do, with the tools at hand, to obtain the result they need." It is problem-focused rather than tool-focused: it starts from a real task, not from a feature of the system.

## Structural conventions

Diátaxis gives concrete writing guidance for a how-to guide:

- State the title as the task the guide demonstrates, so a reader can match the guide to their own goal.
- Use conditional imperatives, for example: "If you want x, do y."
- Present a logical sequence of steps, ordered by what the task requires, not by the structure of the underlying system.
- Maintain momentum: ground each step in what the user does and needs at that point in the task.
- Omit unnecessary explanation and teaching. A how-to guide gives direction, not understanding.
- Omit reference detail that does not serve the immediate step. Link to reference material instead of including it.
- Allow for real-world variation. A how-to guide addresses a practical problem, which can have more than one valid path to the goal; it need not prescribe a single fixed route the way a tutorial does.

## How this differs from a tutorial

A how-to guide is goal-oriented: it serves a user who already has a specific practical objective, and its purpose is to help them complete that task. A tutorial is learning-oriented: it serves a learner, and its purpose is to help them acquire skills and understanding, not to complete a task. Diátaxis describes the how-to guide as "wholly distinct from" the tutorial on this basis: a how-to guide assumes existing competence and focuses on execution; a tutorial assumes no competence and focuses on teaching.
